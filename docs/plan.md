# 포트폴리오 사이트 설계

작성: 2026-11-04. 노션 포트폴리오를 대신할 정적 사이트를 만든다.
개정: 2026-11-12. 2026-11-11 화면 개편(한 칸 장면과 벤토 그리드 → 한 페이지 보통 스크롤)과 AI 프로젝트 구역을 반영했다.

## 1. 사용자 결정

| 항목 | 결정 |
|---|---|
| 저장소 | 기존 GitHub 저장소는 블로그로 둔다. 포트폴리오는 새 저장소 `~/portfolio`다. |
| 구성 | Vite + React + TypeScript + Tailwind CSS. 백엔드는 없다. |
| 배포 | Vercel. GitHub에 push하면 자동 배포한다. |
| 내용 | 실제 이력과 프로젝트 4건을 `src/content/`에 채웠다. |
| 내용 구성 | 참고 글(velog, "중소 SI 취뽀 1탄")의 순서를 따른다. |

## 2. 주소

| 주소 | 이름 | 내용 |
|---|---|---|
| `/` | 상세본 | 기본 포트폴리오. 첫 화면과 구역 6개를 한 페이지에 보통 스크롤로 보인다. |
| `/print` | 단축본 | A4 규격으로 정리한 쪽. 브라우저 인쇄로 PDF를 만든다. |
| 그 밖의 주소 | 없음 | "페이지가 없다" 화면과 상세본 링크를 보인다. |

- 두 주소는 같은 내용 파일을 읽는다. 내용을 한 곳에서만 고친다.
- Vercel `rewrites`로 모든 주소를 `index.html`에 보낸다. 라우팅은 React Router가 한다.

## 3. 상세본 구성 (구역 순서)

사용자 결정(2026-11-05): 심사하는 사람은 30초~1분 동안 본다. 비슷한 내용끼리만 합친다. 주제가 다른 내용(예: 기술과 프로젝트)은 한 구역에 섞지 않는다.

사용자 결정(2026-11-11): 한 칸씩 넘기는 장면을 없애고 보통 스크롤 한 페이지로 바꾼다. 구역 id, 번호, 이름은 `src/domain/sections.ts` 한 곳에서 정한다.

| 번호 | 구역 (id) | 내용 |
|---|---|---|
| 없음 | 첫 화면 | 큰 제목 3줄(`home.ts`), 소개 2줄, 단추 2개(프로젝트 보기, 단축본 PDF), 판독 흐름 카드, 강점 3칸 띠 |
| 01 | 소개 (`about`) | 소개 문단, 강점 3개, 성과 숫자 6칸(`highlights.ts`, 강조 칸 1개) |
| 02 | 기술 (`skills`) | 기술 영역 6개. 기술마다 칩 1개(아이콘 1개와 이름 1개), 쓴 곳(`can`), 아직 부족한 것(`lacks`, 선택) |
| 03 | 프로젝트 (`projects`) | 팀 프로젝트 4건의 펼치는 목록. 펼치면 개요, 맡은 일, 결과, 링크. 첫 번째만 펼친 채로 시작한다 |
| 04 | AI 프로젝트 (`ai-projects`) | Claude Code로 만든 개인 프로젝트 3건(`aiProjects.ts`). 모두 접힌 채로 시작한다. 펼치면 개요와 AI를 쓴 곳, 사용한 AI, 속도와 생산성, 시스템 설계, 문제 해결(상황과 판단), 품질 관리, GitHub·작업 흐름 다이어그램 링크 |
| 05 | 이력 (`career`) | 경력 경로 막대(마지막 단계만 강조), 경력·학력·교육·자격증 목록. 자격증은 이름만 보인다 |
| 없음 | 연락처 (`contact`) | 이메일, GitHub, 블로그(선택), 단축본 PDF. 바닥글과 함께 색을 반전해 보인다 |

- 프로젝트가 늘면 목록의 행만 늘어난다.
- 사용자 결정(2026-11-12): "이 사이트와 기록" 구역을 없앤다. 구조·보안 요점과 CI 단계는 AI 프로젝트의 "포트폴리오 사이트" 항목(시스템 설계, 품질 관리)에 합친다. 시행착오는 사이트에 싣지 않는다.
- 팀 프로젝트의 구성도, 문제와 해결, 배포 설명은 사이트에 싣지 않고 노션 링크(`notionUrl`)로 넘긴다. 내용 파일에도 두지 않는다.
- AI 프로젝트의 작업 흐름은 애니메이션 SVG로 그려 GitHub(`docs/ai-workflow/`)에 둔다. 사이트는 링크(`workflowUrl`)만 둔다.
- 링크 3종(`githubUrl`, `demoUrl`, `notionUrl`)은 선택이다. 값이 없으면 화면에 보이지 않는다.
- 참고 글의 조언을 따른다: 근거 없는 형용사("성실하다")를 쓰지 않는다. 할 줄 아는 기술만 쓴다. 성과는 숫자로 쓴다.

## 4. 단축본 (`/print`)

1. A4 세로(210mm × 297mm), 여백 14mm다. `@page`로 지정한다.
2. 내용은 소개, 경력·학력·교육 이력, 기술 요약, 팀 프로젝트 4개(개요·소개·기술·역할·성과·링크. 링크는 인쇄에서 보이도록 주소를 글자로 쓴다), 연락처다. 목표 분량은 2쪽이다. AI 프로젝트는 넣지 않는다.
3. 쪽 나눔에서 프로젝트 1개가 둘로 나뉘지 않게 한다(`break-inside: avoid`).
4. 화면에는 "PDF로 저장" 단추를 둔다. 단추는 `window.print()`를 부른다. 인쇄할 때 단추는 숨긴다.
5. 움직임을 쓰지 않는다. 흰 바탕, 검은 글자로 인쇄한다.
6. 검색 엔진에는 상세본만 노출한다. `/print`는 `noindex`다.

## 5. 스크롤과 움직임

사용자 결정(2026-11-11): 보통 스크롤이다. 한 칸 장면(scroll-snap, 100svh)과 오른쪽 점 내비게이션은 없앴다. 이유는 화면이 낮으면 내용이 넘쳤고, 높이가 바뀌는 펼치는 목록을 넣을 수 없었기 때문이다.

- 헤더는 위에 붙는다. 구역 링크 6개와 테마 단추가 있다. 지금 보이는 구역의 링크에 밑줄이 간다(IntersectionObserver). 768px 미만에서는 링크를 메뉴 단추로 접는다.
- 움직임은 첫 화면이 열릴 때 한 번이다. 제목과 카드가 차례로 나타난다(CSS 키프레임). 내용은 JS 없이도 보인다. 구역마다 스크롤 등장 효과를 넣지 않는다.
- 프로젝트 펼침은 180ms다. 단추는 `aria-expanded`와 `aria-controls`를 쓰고, 접힌 패널은 `inert`다.
- `prefers-reduced-motion: reduce`이면 움직임을 모두 끈다.
- 키보드로 모든 링크와 단추에 갈 수 있다. 초점 표시를 보인다.

## 6. 디자인 방향 (2026-11-11 개편)

사용자 결정(2026-11-11): 참고 사이트 2개를 섞는다. 밝고 차분한 사이트를 기반으로 하고, 다른 사이트에서 큰 구역 번호, 굵은 테두리의 성과 숫자 칸, 펼치는 목록, 경력 경로 막대, 다크 모드 단추를 가져온다. 이전 디자인(어두운 네이비 바탕, 네온 포인트, 벤토 그리드, 2026-11-05)은 쓰지 않는다.

### 6.1 용어

| 용어 | 뜻 |
|---|---|
| 구역 | 페이지를 주제로 나눈 부분. 번호(01~05)와 id가 있다. 연락처는 번호가 없다 |
| 펼치는 목록 | 행마다 +/− 단추가 있고, 누르면 자세한 내용이 열리는 목록 |
| 기술 글자 | 코드, 명령어, 날짜, 작은 라벨. JetBrains Mono로 쓴다 |

### 6.2 색

밝은 화면이 기본이다. 저장된 선택이 없으면 시스템 설정(`prefers-color-scheme`)을 따른다. 헤더 단추로 바꾸고, 선택은 `localStorage`에 저장한다. 단추 글자는 누르면 바뀔 테마("다크 모드" 또는 "밝은 모드")다.

| 이름 | 밝게 | 어둡게 | 쓰는 곳 |
|---|---|---|---|
| `--bg` | `#F3F4EE` | `#131712` | 페이지 바탕 |
| `--panel` | `#E9ECE1` | `#1B2119` | 카드 바탕 |
| `--ink` | `#1F3326` | `#E5EADC` | 제목, 강조 글자 |
| `--body` | `#4A5747` | `#B8C1AE` | 본문, 작은 글자 |
| `--muted` | `#6E7A66` | `#87927D` | 큰 글자와 장식 선에만 쓴다 |
| `--line` | `#D5DACB` | `#2E372C` | 얇은 구분선 |
| `--rule` | `#1F3326` | `#E5EADC` | 성과 숫자 칸의 굵은 테두리 |
| `--accent` | `#5E7A4A` | `#9DB57F` | 강조 글자, 판단 문장의 세로선 |
| `--accent-fill` | `#C8D8A4` | `#3D5230` | 강조 칸 1개, 현재 경력 단계 |
| `--inv-*` | 숲색 바탕, 밝은 글자 | 밝은 바탕, 짙은 글자 | 연락처 구역과 바닥글(색 반전) |

- 작은 글자의 대비는 WCAG AA(4.5:1) 이상이다. `--muted`는 밝은 바탕에서 약 4.1:1이라 작은 글자에 쓰지 않는다.
- 제목 안의 단어 1개만 색을 바꾸지 않는다. 예외는 첫 화면 큰 제목의 마지막 줄 1개다.
- 강조 채움 칸은 한 묶음에 1개만 둔다.
- 단축본(`/print`)은 흰 바탕, 검은 글자 그대로다.

### 6.3 글꼴

| 글꼴 | 쓰는 곳 |
|---|---|
| Pretendard | 제목, 본문, 단추 등 기본 글자 |
| Archivo (굵기 900, 너비 125%) | 큰 구역 번호와 성과 숫자 |
| JetBrains Mono | 기술 이름 칩, 날짜, 작은 라벨, 코드와 명령어 |

- 세 글꼴 모두 npm 패키지로 자체 제공한다. 외부 CDN을 쓰지 않는다.

### 6.3.1 기술 아이콘

사용자 결정(2026-11-05): 기술 이름마다 그 기술의 아이콘을 붙인다. 사용자 결정(2026-11-12): 칩 1개에는 아이콘 1개와 기술 이름 1개만 둔다.

1. 아이콘은 npm 패키지 `simple-icons`(CC0)의 SVG 경로를 쓴다. 쓰는 아이콘만 가져와 번들에 넣는다. 외부 CDN과 이미지 요청을 쓰지 않는다.
2. 아이콘은 inline SVG(`fill="currentColor"`)로 그린다. 색은 기술 이름 글자와 같다. 브랜드 색은 쓰지 않는다.
3. 내용 파일의 기술마다 `{ name, icon? }`를 둔다. 키와 SVG의 연결은 `src/ui/techIcons.ts` 한 곳에서 한다.
4. 아이콘이 없는 기술(예: DRF)은 글자만 보인다. 아이콘을 지어내지 않는다.
5. 아이콘은 장식이다. `aria-hidden="true"`로 두고 기술 이름 글자를 그대로 보인다.
6. 시험이 내용 파일의 모든 아이콘 키가 `techIcons.ts`에 있는지, 칩마다 아이콘이 1개 이하인지 검사한다.

### 6.4 배치

1. 본문 최대 폭은 1240px이다. 본문 줄 길이는 약 70자 이하다.
2. 1024px 이상: 첫 화면 2열(왼쪽 제목, 오른쪽 카드), 성과 숫자 3열, 펼침 내용 3열이다.
3. 768~1023px: 첫 화면 1열(카드는 제목 아래), 성과 숫자 2열, 펼침 내용 2열이다.
4. 768px 미만: 좌우 여백 16px, 모든 격자 1열, 큰 번호는 clamp로 줄인다. 360px 폭에서도 가로 스크롤이 없다.
5. 모서리는 카드 8px, 칩 6px이다. 성과 숫자 칸과 +/− 단추는 각지게 둔다.
6. 첫 화면 카드는 기울이지 않는다(사용자 결정, 2026-11-12).

### 6.5 구역별 배치

| 구역 | 배치 |
|---|---|
| 첫 화면 | 왼쪽 큰 제목·소개·단추, 오른쪽 카드(판독 흐름 도식 "판독 요청 → 작업 큐 → GPU 추론 → 소견문"과 이름, 관심 분야, 교육, 최근 결과). 아래 3칸 띠 |
| 소개 | 왼쪽 소개 문단, 오른쪽 강점 3개. 아래 굵은 테두리 성과 숫자 3열 × 2행 |
| 기술 | 기술 영역 카드 2열 |
| 프로젝트, AI 프로젝트 | 펼치는 목록. 행은 번호(`P/01`, `A/01`), 이름, 기간, +/− 단추 |
| 이력 | 경력 경로 막대 4칸, 아래 목록 |
| 연락처 | 반전 색 바탕. 제목 "연락처", 이메일·GitHub·단축본 행 |

### 6.6 피할 것

- 크림 바탕 + 테라코타, 검정 바탕 + 형광 강조
- 모든 카드에 같은 그림자, 장식용 그라데이션
- 모든 제목 위의 영문 대문자 꼬리표
- 구역마다 반복되는 스크롤 등장 효과
- 번호는 실제 순서가 있는 곳(구역 순서, 목록의 행)에만 쓴다

## 7. 구조와 보안 (사이트에 소개하는 내용)

### 7.1 구조

| 폴더 | 역할 | 의존 방향 |
|---|---|---|
| `src/domain/` | 내용의 타입 정의, 구역 목록, 경력 경로 계산. React를 모른다 | 없음 |
| `src/content/` | 실제 내용 데이터. 사용자가 고치는 유일한 곳 | domain |
| `src/features/` | 구역별 화면 부품(상세본), 단축본, 없는 주소 | domain, ui |
| `src/ui/` | 공용 화면 부품, 현재 구역 훅, 테마 읽기·쓰기 | 없음 |
| `src/app/` | 라우터와 페이지 조립 | 모두 |

- 내용과 화면을 나눈다. 새 프로젝트를 더하면 내용 파일에 항목 1개만 더한다.
- 상세본과 단축본은 같은 내용을 다른 화면 부품으로 보인다.
- 시험(Vitest)이 내용 형식을 검사한다. 예: 프로젝트마다 역할과 결과가 있다. 링크는 `https://`다.

### 7.2 보안과 개인 정보

1. 전화번호, 주소, 생년월일, 지역을 싣지 않는다.
2. 이메일은 HTML 원문에 그대로 두지 않는다. 화면에서 조립해 수집 프로그램을 줄인다(완전한 차단은 아니다).
3. Vercel 응답 헤더를 정한다: CSP(`default-src 'self'`, 외부 스크립트 금지, `frame-ancestors 'none'`), HSTS, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`(카메라·마이크·위치 끔).
4. 분석 도구와 추적 스크립트를 넣지 않는다. 외부 글꼴과 CDN을 쓰지 않는다.
5. 배포본에 소스 맵을 넣지 않는다.
6. 의존성은 lockfile로 고정한다. CI가 `npm audit --audit-level=high`를 돌린다. Dependabot이 주 1회 갱신을 제안한다.
7. 비밀 값이 없는 구조다. 배포는 Vercel의 GitHub 연동을 쓰므로 GitHub에 Vercel 토큰을 두지 않는다.

## 8. CI와 배포

1. GitHub Actions `ci.yml`이 push와 pull request마다 `npm ci`, lint, 타입 검사, 시험, 빌드, `npm audit`을 돌린다.
2. Vercel이 GitHub 저장소와 연동해 `main` push를 운영 배포로, pull request를 미리보기 배포로 만든다.
3. GitHub 저장소 보호 규칙으로 CI 통과 전 병합을 막는다(사용자가 설정한다).

사용자가 할 일 (계정과 외부 공개는 사용자가 직접 한다):

1. GitHub 저장소 생성과 공개 범위를 승인한다.
2. Vercel에 로그인한다.
3. Vercel에서 저장소를 가져온다(Import). 설정은 기본값(Vite)이다.
