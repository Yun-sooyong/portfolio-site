# 이력서 · 포트폴리오 · 깃허브 · 노션 나누기

작성: 2026-11-06. 사용자가 준 구성안(`이력서-포폴-노션-깃허브-구성.md`)을 적용한다.

## 1. 역할 (사용자 결정)

| 문서 | 무엇을 쓰나 | 이 작업에서 할 일 |
|---|---|---|
| 이력서 | 기존 사람인 이력서 | 고치지 않는다. 프로젝트를 고르는 기준으로만 쓴다 |
| 포트폴리오 | 이 사이트 | 구성안 2장대로 고친다 |
| 깃허브 | 고른 프로젝트 저장소의 README | 구성안 3장대로 다듬는다. 프로필 README는 고치지 않는다 |
| 노션 | 프로젝트마다 새 페이지 | 구성안 4장대로 만든다. 기존 노션 포트폴리오는 고치지 않는다 |

## 2. 프로젝트 고르기

1. 기존 이력서와 기존 노션 포트폴리오에 있는 프로젝트를 기준으로 3~4개를 고른다.
2. 읽기 전용 하위 에이전트 1개가 이력서와 기존 포트폴리오를 읽는다. 사용자가 허용했다(2026-11-06).
3. 그 에이전트는 프로젝트 단위 사실만 보고한다: 이름, 기간, 개인/팀, 역할, 기술, 성과 숫자, 저장소.
4. 그 에이전트는 전화번호, 주소, 생년월일, 이메일, 주민번호 같은 개인 정보를 보고에 쓰지 않는다.
5. 보고 내용은 Git에 넣지 않는다. 사이트에는 사용자가 확인한 내용만 넣는다.

## 3. 내용 출처의 우선순위

1. 저장소의 코드, README, 커밋 기록에서 확인되는 사실
2. 1에 없으면 이력서와 기존 포트폴리오에서 읽은 사실 (2장의 하위 에이전트)
3. 둘 다 없으면 빈칸으로 두고 사용자에게 묻는다. 숫자를 지어내지 않는다.

## 4. 포트폴리오 사이트 변경 (구성안 2장)

| 장면 | 내용 |
|---|---|
| 소개와 이력 | 간단한 본인 정보, 학력, 교육 이력(기간, 배운 기술, 한 줄 설명, 스터디), 자격증(필기 합격 포함). 교육과 자격증은 한두 줄 |
| 기술 | 실제로 쓴 기술만 |
| 프로젝트 목록 | 3~4개 |
| 프로젝트 | 프로젝트마다 1장면. 이름, 기간, 간단한 설명, 기술, 소개, 성과, 맡은 역할, GitHub 링크, 데모 링크, 노션 링크 |
| 이 사이트와 기록 | "만든 방식"과 "시행착오"를 1장면으로 줄인다. 자세한 내용은 이 저장소 README와 노션 링크 |
| 연락처 | 그대로 |

- 프로젝트 상세 설명(구성도, 트러블슈팅 전체)은 노션으로 넘긴다. 사이트에는 요약만 둔다.

## 5. 깃허브 README (구성안 3장)

1. 3분 안에 읽는 분량이다. 구조도는 1장이다. 이미지는 적게 쓴다.
2. 항목: 프로젝트 정의, 핵심 가치, 구조, 기술 스펙 표, 인프라 구성 표, 사용한 AI 모델 스펙(있으면), 실행 방법.
3. 바꾼 README는 사용자가 확인한 뒤 push한다. 공개 저장소 변경은 외부 공개다.

## 6. 노션 (구성안 4장)

1. 새 상위 페이지 1개 아래에 프로젝트마다 페이지 1개를 만든다. 처음에는 비공개다.
2. 페이지 맨 위(토글 밖): 한 줄 요약, 핵심 성과 3개, 아키텍처 그림 1장 자리.
3. 그 아래는 토글: 기술 스펙·인프라 표, AI 모델 스펙, 데이터 흐름, 화면 구조, API, 트러블슈팅(상황, 원인 분석, 해결 과정, 결과).
4. 그림은 사용자가 넣는다. 그림 자리에 무엇을 넣을지 적어 둔다.

## 7. 순서 (구성안 7장)

1. 프로젝트를 고른다(2장).
2. 프로젝트 1개로 README와 노션 페이지 틀을 만들고 사용자 확인을 받는다.
3. 같은 틀을 나머지 프로젝트에 적용한다.
4. 사이트에 정리한다. 사이트 구조 변경(4장)은 1~3과 따로 먼저 해 둔다.
